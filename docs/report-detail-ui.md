# 報告詳情頁資訊架構

本次只調整前端呈現與互動，沿用既有 API、統計與評估流程。保留左側導航；依後續使用者回饋，測試列表改為完整寬度，證據詳情以右側抽屜按需開啟。

## 預設資訊層級

1. Header：報告名稱、Agent、執行次數與調用結果、精簡執行紀錄切換、單一匯出選單。
2. KPI：主要分組的規則用例總數、通過、未通過、無法判斷；AI 評估進度獨立標示回答口徑。
3. AI 摘要：所選批次的品質判定、已判定回答符合率、分組後的評估異常與常用操作。
4. 測試明細：列表使用完整寬度，點擊案例或該行後開啟 800px 寬的右側明細抽屜；手機全螢幕。保留輸入、輸出、參考回答、AI 差距、規則依據與執行過程。內文使用 14px 正文字體，抽屜內只有一個主要捲動區。

## 統計口徑

- 前四個 KPI 直接使用 `metrics.branches[0].conclusion`。頁面明示分組；通過＋未通過＋無法判斷＝該分組用例總數。未通過包含既有判定中的執行失敗，無法判斷不等於答案失敗。
- Header 的執行進度、調用成功與失敗使用所選執行批次的 `RunSummary`，與答案品質分開。
- AI 完成度與品質沿用 `summarizeAiReport`，按回答／試驗計數，可能包含多分組或重複執行；不與規則用例數混加。
- AI 符合率明示分母為可判定回答；評估失敗、中斷、無法判定與未送評仍獨立呈現。
- 錯誤分組只轉換顯示名稱，例如輸出未完成、格式或引用不符、超時、連線異常。原始錯誤不修改，於詳情抽屜內展開查看。

## 功能入口

- 執行紀錄仍使用 `RunSwitcher`，僅報告頁啟用 compact 外觀。
- 評估詳情抽屜保留 AI 批次選擇、完整評估、失敗補評、模型管理及原始錯誤。
- 差距與建議抽屜保留問題摘要與建議，可直接選中下方對應試驗查看證據。
- 「查看原文證據」及帶 `trial` 參數的直接連結會開啟對應試驗明細；明細抽屜支援上一條／下一條（依目前列表篩選）、關閉按鈕和 Escape。
- 規則與比較抽屜保留規則結論、樣本說明、前版比較與 A/B 指標。
- 匯出選單保留 PDF、HTML、JSON，沿用目前的執行與 AI 批次參數。移除頁首重複的導出入口；篩選統一放在明細列表旁。

## 版面與本地驗證

上半部不設獨立滾動容器；常態桌面保留下半部列表的捲動，明細以浮層獨立閱讀，不擠窄列表。短螢幕／窄螢幕使用頁面主滾動，浮層詳情不擠高摘要。手機表格保留欄位並在列表內橫向瀏覽。
