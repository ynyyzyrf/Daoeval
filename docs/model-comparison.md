# 模型對比

1. Agent 接入中為同一 Agent 建立各模型版本，設定真正的 providerId 或 HTTP Body.model；版本名稱只供辨認。
2. 新建實驗，選測試集，將測試方式改為「模型對比：同一 Agent，只換模型」。
3. 選一個基準版本，再加入其他模型版本（最多八組，含基準）。所有組使用同一測試集、評分規則及重複次數。
4. 建立後在實驗詳情開始執行。建立實驗本身不調用模型。
5. 打開報告的「模型／版本對比」。若要比較回答品質，在評估詳情發起同一批次的完整 AI 評估。
6. 點案例可在右側並排查看各模型原始回答、耗時、AI 判定及引用證據；可篩選改善、退步、無變化或不可比較。
7. PDF、HTML、JSON 匯出沿用目前選擇的執行批次及 AI 評估批次，包含模型對比。

## 統計口徑

- 執行統計採調用次數；每個案例、每次重複分開計算。
- AI 評估進度以成功取得非空回答且具備參考答案的調用為分母。未評、評估異常、處理中另列。
- 已判定符合率 = 符合 /（符合 + 部分符合 + 不符合）。無法判定另列，不能當回答失敗，也不能推論全批通過率。
- 平均回答耗時及 P95 只使用成功調用。超時次數單獨列出。Oumi 優先使用遠端回傳的起止時間，缺少時採本地量測；不含 AI 評審時間，不代表首字延遲。
- 改善／退步按同一案例、同一重複序號，將各候選組與基準組配對。判定次序為符合 > 部分符合 > 不符合；沒有完整可判定結果時列為不可比較。
- 補評批次若沿用歷史結果，無法確認個別評估提示版本時，不計改善／退步；請完整重新評估取得一致標準。
- 資料只從指定執行批次及所選 AI 批次取得，不拼接其他執行的較佳答案。

## 邊界

模型對比建立前會檢查：同一 Agent、版本與分組不重複、模型實際路由不同，以及模型之外的本地配置一致。若要同時改 Prompt 或其他設定，改用一般多版本對比。

遠端可變的 Prompt、Skill、工具與知識庫無法由本地快照保證不變，需在遠端固定配置後執行。既有測試與分享快照不會補寫或重新發送。此功能驗證使用隔離資料庫與模擬模型，並非三個正式模型的實際比較結論。

驗證：`npm run check:model-comparison`、`npm run check:version-names`、`npm run typecheck`、`npm run build:web`。
