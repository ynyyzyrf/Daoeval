# Daoeval 產品化說明 v1.0

狀態：待確認 | 撰寫：Vera（產品） | 日期：2026-10-30 | 對應：需求文檔 V1.0（同一目錄外的 outputs 目錄）

---

## 1. 這輪要解決什麼

現在能跑通流程，但看就知道是示範品。不是功能不夠，是這三件事：

**一、頁面在講開發進度。** 標題下面寫「V1.0 可重現四元組 + 統一結構適配層 + 規則評分 + 批量執行 + A/B 報告（Oumi / Dify 適配器待範例接入）」，頁尾寫「已落地：……待範例：……」。這些是給開發看的進度，不是給使用者看的產品。產品頁面上不該出現這類文字。

**二、頂欄有「一鍵灌入示範資料」。** 這是 demo 最重的信號，等於承認沒有真實資料也能看。移到設定頁的開發者工具裡，主介面不放。

**三、導航和密度不夠。** 只有四個文字頁籤，接入表單跟已接入清單堆在同一頁；清單每張卡片把模型／Prompt／框架三個欄位往下排，十幾個 Agent 就要滾好幾屏，沒有搜尋、篩選、分頁。

目標：不靠人在旁邊解釋，同事打開就能自己走完「接入 → 建測試集 → 跑批量 → 看報告」。

## 2. 信息架構

改成左側全局導航 + 三層結構（列表 → 詳情 → 子頁）。不要再用頁籤切換一種東西。

```
概覽
Agent        列表 → Agent 詳情（配置 / 版本 / 最近試驗）
測試集        列表 → 測試集詳情（案例 / 版本 / 評分規則）
實驗          列表 → 實驗詳情（凍結配置 / 跑批 / 指標）
報告          列表 → 報告詳情（對比 / 下鑽 / 導出）
設定          開發者工具 / 術語表 / 關於
```

- 側欄常駐、當前項高亮；詳情頁頂部有麵包屑（測試集 / 金融客服問答集 / v3）。
- 全局搜尋放側欄上方，搜 Agent 名稱、測試集名稱、實驗名稱。
- 「開發者工具」（示範資料、模擬端點、金鑰來源）只出現在設定頁，且要二次點開。

## 3. 每一頁算做完的標準

### 概覽
最近 5 個實驗（含狀態與樣本量）、最近一次報告的結論摘要、待處理項（未完成的實驗、失敗的跑批）。全新環境時不是空白，給「接入第一個 Agent」的引導路徑。

### Agent
- 接入表單拆成三步：**連線 → 欄位映射 → 驗證預覽**。可上一步、下一步；第二步才出現映射欄位；第三步顯示「打了一次真實請求」的回應摘要與五個映射欄位的解析結果，通過才能存。
- 清單：卡片或表格二選一（預設表格，欄位：名稱、平台類型、版本數、最近試驗、最近通過率、狀態、更新時間）。
- 搜尋按名稱；篩選按平台類型與狀態（可用／待適配／停用）；排序按名稱與更新時間；分頁每頁 20。
- 空狀態：「還沒有接入任何 Agent」＋主要按鈕。

### 測試集
- 列表：名稱、案例數、版本號、最後發佈時間、適用範圍。
- 詳情兩區：**案例**（表格，欄位：名稱、類型、讀寫、逾時、優先級；可搜尋、按類型篩、批量選取、行內進入編輯抽屜）與**版本**（已發佈版本清單、每版指標閾值與規則集引用、是否被實驗引用）。
- 案例編輯用右側抽屜，不跳頁。

### 實驗
- 列表：名稱、類型（A/B 或橫向）、分支數、樣本量、狀態、建立時間；狀態篩選。
- 詳情三區：**凍結配置**（四元組與快照時間，唯讀）、**跑批控制**（並發、重複次數、開始／暫停／繼續／取消、進度條、失敗分類計數）、**指標**（各分支並排，N/A 帶原因）。

### 報告
- 選實驗與兩個分支做對比；指標卡、N/A 原因彙總、樣本量與波動提示、失敗案例、下鑽到單條試驗。
- 導出 JSON／HTML／PDF 三個入口放同一處，導出件數值與頁面一致。

### 設定
開發者工具（示範資料、模擬端點位址、金鑰來源）、術語表（N/A 三態、四元組、預算分類等）、版本資訊。

## 4. 每頁都要有的通用能力

這是「像產品」跟「像 demo」差最多的地方，逐條驗：

1. **載入**：列表與詳情用骨架屏，不用全螢幕遮罩；超過 400ms 才顯示。
2. **空狀態**：每個列表都有，含一句說明與一個下一步動作。
3. **錯誤**：表單錯誤行內顯示在欄位下方；請求失敗用右上 toast，可手動關。
4. **按鈕狀態**：常態／懸停／按下／聚焦／禁用／載入中六態齊備，載入中保持原寬並禁用重複提交。
5. **列表能力**：搜尋、篩選、排序、分頁四件套，50 條資料下不卡。
6. **格式統一**：時間 `2026-10-30 16:20`；耗時 `258 ms`；百分比一位小數；N/A 不寫成 0 或 `-`。
7. **鍵盤**：Tab 可走完表單，focus 有可見外環，對話框 Esc 關閉。

## 5. 明確不做（這輪）

登入、權限、多租戶；AI 評分與診斷建議；Oumi／Dify 實接；雲端部署與多機；行動端適配；國際化。

## 6. 驗收（8 條，逐條可勾）

1. 主介面任何位置不出現「已落地／待範例／V1.0 可重現四元組」這類開發進度文字；示範資料只在設定頁的開發者工具內。
2. 左側導航六項，當前頁高亮；詳情頁有麵包屑可回上層。
3. Agent、測試集、實驗三個列表都有搜尋、篩選、排序、分頁，50 條資料下操作不卡。
4. 接入 Agent 為三步式，可回退；驗證結果以面板呈現（回應摘要＋五個映射解析結果），不是一行文字。
5. 每個頁面具備骨架、空狀態、錯誤態；所有按鈕有六態。
6. 報告頁可選兩分支對比，導出 JSON／HTML／PDF，導出件數值與頁面一致。
7. 組件內不硬寫色值與字級，全部取 design token（`grep -E "#[0-9a-fA-F]{3,8}" web/src/components/*.tsx` 應無結果）。
8. 一個沒看過這套系統的同事，不靠口頭解釋，能自己走完接入 → 建測試集 → 跑批量 → 看報告。

## 7. 交付順序建議

先做導航、資訊架構與 Agent 三步接入（第 2、3 節的 Agent 段），這是「一眼看出是產品」的部分；再做列表四件套與通用狀態；最後才是報告頁細節與設定頁。理由：導航和接入是使用者第一眼看到的兩件事，先立骨架再談細節，避免在舊結構上打磨又被推翻。
