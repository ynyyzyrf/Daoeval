---

## 一、這份用例的狀態

**截至 2026-10-31，這個功能還沒落地**（`exceljs ^4.4.0` 已進 `package.json`，但 `src/`、`scripts/` 全域搜 `excel` 仍是零命中，端點未定；`PUT /api/test-sets/:id/cases` 仍是唯一的案例寫入入口）。所以：

- 用例全部寫成**黑盒**，只依賴規格定義的輸入輸出，不依賴實作。
- 「關聯代碼位置」這一欄先標規格條款（`§x`）；Rune 落地後補上 `文件:行號`，回歸時才有定位能力。
- 假定端點：`GET /api/test-sets/template?kind=blank|sample`、`POST /api/test-sets/import`（multipart）。名字若不同，用例照樣適用，只換請求路徑。

## 二、執行環境

- 臨時資料目錄 + 自己的端口，**不要碰 `.data/`、不要佔 5280**（同上一批的硬規則）。
- 導入產生的測試集會直接進庫，回歸時每個用例開始前記下 `SELECT COUNT(*) FROM test_set` 與 `SELECT MAX(rowid) FROM test_case`，結束後比對，用來驗原子性。
- 造數工具：本機已有 Python `openpyxl 3.1.5`（我已驗證可用），夠造出下面所有畸形檔；等 `exceljs` 落地後，正式 fixture 建議改用它生成，與產品產生模板的庫保持一致，避免「用 A 庫造的檔 B 庫讀不出來」這種假缺陷。
- **fixture 清單**（每個檔單獨存在 `.tmp/tess-excel/<用途>.xlsx`）：

  | 檔案 | 內容 | 用於 |
  | --- | --- | --- |
  | `blank.xlsx` | 平台下載的空白模板 | X01 X03 |
  | `sample.xlsx` | 平台下載的 16 條範例 | X02 X51 |
  | `ok-15-bad-16.xlsx` | 前 15 行合法，第 16 行類型填「安全」 | X25 |
  | `multi-error.xlsx` | 第 3、7、12、15 行各一種錯 | X26 |
  | `bad-version.xlsx` | `template_version` 改成 2 | X08 |
  | `bad-header.xlsx` | 刪掉 L 列「備註」表頭 | X09 |
  | `shuffled.xlsx` | A/B 兩欄互換，表頭文字不變 | X10 X44 |
  | `formula.xlsx` | A2=`=1+1`、A3=`=HYPERLINK(...)`、C2=`+1` | X39 X40 |
  | `merged.xlsx` | A1:L1 合併後填「範例」 | X42 |
  | `empty.xlsx` | 只有表頭、零資料行 | X43 |
  | `big-499/500/501.xlsx` | 499/500/501 條合法案例 | X13 |
  | `type-shift.xlsx` | A 列數字、H 列日期、J 列布林 | X47 |
  | `long.xlsx` | A2 十萬字符、C2 十萬字符 | X41 |

## 三、用例

編號 `TC-X01`…`TC-X58`，與核心不變量的 `TC-1xx`…`TC-5xx` 不衝突，回歸時可以單獨挑一組跑。

### A 模板與下載

#### TC-X01　空白模板結構正確
- **優先級**：P0
- **前置條件**：服務已啟動
- **步驟**：`GET /api/test-sets/template?kind=blank`，用 Excel 與 openpyxl 各讀一次
- **預期結果**：Sheet 名恰為「案例」「填寫說明」兩張；「案例」表頭 A–L 十二列，名稱與 §3 表格逐字一致；B/E/I/J 四列有資料驗證（下拉）；範例行數為 0；說明頁有 `template_version` 單元格且值為 1
- **關聯**：規格 §3、§7

#### TC-X02　標準範例集可直接導入
- **優先級**：P0
- **前置條件**：同 X01
- **步驟**：下載 `kind=sample`，直接導入（不做任何修改）
- **預期結果**：導入成功，生成草稿測試集，案例數 16；八種類型各 2 條；類型分佈與附錄 A 一致
- **關聯**：規格 §3「標準範例集」、驗收 2

#### TC-X03　空白模板直接導入
- **優先級**：P1
- **前置條件**：`blank.xlsx`
- **步驟**：直接導入
- **預期結果**：拒絕並提示「沒有案例資料」類訊息，**不能**生成一個 0 條案例的草稿（規格未定義此情形，見缺口 W06）

#### TC-X04　下載檔本身可正常開啟

- **步驟**：用 Excel 打開空白模板，另存一份再讀；檢查有無損毀修復提示
- **預期結果**：無損毀提示；格式、下拉、欄寬保留

#### TC-X05　說明頁內容完整

- **關聯**：規格 §3「不接受 CSV 代替」

### C 逐行校驗（七類錯誤）

#### TC-X15　必填缺失
- **優先級**：P0
- **前置條件**：一份檔裡第 2 行缺 A、第 3 行缺 B、第 4 行缺 C、第 5 行缺 E
- **步驟**：導入
- **預期結果**：一次回報四條錯誤，每條帶行號與欄位名（「第 2 行：案例名稱為必填」…），全部列出而不是只報第一條
- **關聯**：規格 §4.2、驗收 3

#### TC-X16　枚舉不認識
- **優先級**：P0
- **前置條件**：B 填「安全」、E 填「AI」、I 填「緊急」、J 填「只讀」
- **步驟**：導入
- **預期結果**：四條錯誤，訊息裡要帶**實際值**與**允許值清單**（「案例類型『安全』不在允許值內」）。注意「安全性」是合法值、「安全」不是，這一對最容易誤判
- **關聯**：規格 §4.2

#### TC-X17　條件必填缺失（三種組合）
- **優先級**：P0
- **前置條件**：三行：E=規則且 F 空；E=Rubric 且 G 空；E=規則＋Rubric 且 F、G 都空
- **步驟**：導入
- **預期結果**：三行都報錯，訊息點明「評分方式含『規則』但規則欄為空」這種具體關係。**另外要驗**：E=純規則但 G 有值、E=純 Rubric 但 F 有值，這兩種是忽略還是報錯（缺口 W10）
- **關聯**：規格 §4.2

#### TC-X18　規則 JSON 語法錯
- **優先級**：P0
- **前置條件**：F 填 `[{"kind":"contains","path":"output","value":"模型"` （缺右括號）

#### TC-X19　規則算子不支援

#### TC-X20　規則屬性缺失或型別錯
- **優先級**：P1
- **前置條件**：三行：`[{"kind":"contains"}]`（缺 path/value）、`[{"kind":"max_length","path":"output","value":"一百"}]`（值型別錯）、`[]`（空規則陣列）

### D 整批原子性

#### TC-X25　前 15 行正確、第 16 行類型錯　← 驗收硬指標
- **優先級**：P0
- **前置條件**：`ok-15-bad-16.xlsx`（前 15 行完全合法，第 16 行 B 列填「安全」）
- **步驟**：
  1. 導入前記下 `test_set` / `test_case` 行數
  2. 導入
  3. 導入後再記一次
- **預期結果**：拒絕；錯誤清單**只有一條**且指向第 16 行；`test_set`、`test_case`、`test_set_version` 三張表行數完全不變。**這是整批語義的核心，任何一行入庫都算 FAIL**
- **關聯**：規格 §4.3

#### TC-X26　多行錯誤時清單完整且有序
- **優先級**：P0
- **前置條件**：`multi-error.xlsx`（第 3、7、12、15 行各一種錯）
- **步驟**：導入，記錄回應
- **預期結果**：四條錯誤全部返回，按行號升序；每條含 `行號`、`欄位`、`原因` 三個結構化欄位（不只是拼好的字串），前端要能逐條定位
- **關聯**：規格 §4.2、§7「錯誤清單結構化回傳」

#### TC-X27　拒絕後庫裡零殘留
- **優先級**：P0
- **前置條件**：同 X25
- **步驟**：導入失敗後，直接查庫：`SELECT * FROM test_set ORDER BY created_at DESC LIMIT 3`、`SELECT * FROM test_case ORDER BY rowid DESC LIMIT 3`
- **預期結果**：查不到本次導入產生的任何測試集、案例或版本；若有自動遞增 id，也不能有「跳號後留下的空殼」
- **關聯**：規格 §4.3、§7「交易包裹」

#### TC-X28　失敗 → 修正 → 重導
- **優先級**：P0
- **前置條件**：同 X25
- **步驟**：導入失敗一次，把第 16 行改對，再導入一次
- **預期結果**：第二次成功，只產生**一個**測試集、16 條案例；前一次的失敗沒有留下任何可選中或遮蔽的對象（例如列表裡不能有同名空測試集）
- **關聯**：規格 §4.3

#### TC-X29　「僅導入通過的行」開關與整批語義的衝突
- **優先級**：P0（等規格確認後可能降級）
- **前置條件**：規格 §4.3 寫「若確實需要累加，導入結果頁提供『僅導入通過的行』複選，預設關閉」；但 §8 待確認第 2 條又寫「我傾向先不做」，兩處矛盾（缺口 W02）
- **步驟**：針對 Rune 的實際實作分三種情況驗：
  1. 未實作該開關 → 只需確認結果頁沒有它的殘留 UI
  2. 已實作且預設關閉 → 預設下必須 all-or-nothing；勾選後才部分寫入，且必須二次確認並明示「僅寫入 M 條，其餘 N 條丟棄」
  3. 已實作但預設開啟 → 直接判 FAIL
- **預期結果**：預設路徑永遠是 all-or-nothing，不留任何「部分成功但沒告訴使用者」的口子
- **關聯**：規格 §4.3、§8

### E 導入中斷

#### TC-X30　上傳到一半斷網
- **優先級**：P0
- **前置條件**：一份 4MB 左右的合法檔，用限速上傳（Chrome DevTools Slow 3G）或 `curl --limit-rate 200k`
- **步驟**：上傳到約 50% 時斷開（拔網／取消請求）
- **預期結果**：服務端不產生任何測試集與案例；連線斷開不應在日誌留下未捕獲的例外堆疊
- **關聯**：規格 §7「解析完即刪」（中斷語義未定義，見缺口 W12）

#### TC-X31　解析與寫入途中殺進程
- **優先級**：P0
- **前置條件**：一份接近 500 行的合法檔
- **步驟**：導入後立刻 `Stop-Process` 掉平台進程（不要用 `taskkill /IM node.exe`，會誤殺別的 Bot）；重啟，查庫
- **預期結果**：重啟後 `test_set`/`test_case` 沒有半批資料；若寫入已開始，交易回滾；啟動日誌無「半批殘留」警告
- **關聯**：規格 §4.3、§7

#### TC-X32　中斷後重新導入
- **優先級**：P1
- **前置條件**：X30 或 X31 之後
- **步驟**：重新導入同一份檔
- **預期結果**：正常成功，只產生一份測試集。不能因為上次中斷而報「名稱已存在」或留下半份數據

#### TC-X33　臨時檔清理
- **優先級**：P0
- **前置條件**：無
- **步驟**：導入成功、導入失敗、上傳中斷三種情況各一次，分別檢查系統臨時目錄與專案目錄有無殘留 `.xlsx`

### F 重複導入

> 規格 §4.4 工作區版本已改成「只做新建測試集草稿，追加模式 V1.0 不做」。所以**同一份檔導入兩次，按規格會得到兩個同名測試集**。這一行為必須被驗證並在界面上說清楚，否則使用者會以為第二次覆蓋了第一次。

#### TC-X34　同一份檔連續導入兩次
- **優先級**：P0

- **步驟**：導入兩次，記錄兩次結果
- **預期結果**：**按規格**：產生兩個獨立草稿測試集，各自 16 條；兩者內容相同但 id 不同。**界面必須在第二次導入時明確告知會新建一份**（而不是讓人以為在更新）。若 Rune 實作成覆蓋或拒絕，也必須一致且可預測，並回寫規格（缺口 W03）

#### TC-X35　同名測試集在列表裡可區分

- **步驟**：`GET /api/test-sets`，看列表
- **預期結果**：兩條都能看到，至少靠建立時間或案例數能分辨；不能出現「兩條長得完全一樣、點進去不知道是哪個」

#### TC-X36　已發佈版本不受二次導入影響

#### TC-X37　改檔後再導入

### G 惡意與畸形輸入

#### TC-X39　公式注入（`=` 開頭）
- **優先級**：P0
- **前置條件**：`formula.xlsx`：A2=`=1+1`、A3=`=HYPERLINK("http://evil.example","點我")`、A4=`=cmd|'/c calc'!A0`、C2=`=SUM(1,2)`
- **步驟**：導入後：1) 查庫裡的值；2) 導出 Excel 再用 openpyxl 讀 `cell.data_type`；3) 用 Excel 打開導出件
- **預期結果**：庫裡存的是**原樣文字**（`=1+1` 就是這四個字元）；導出件的 `data_type` 是字串不是公式；Excel 打開時不彈安全性提示、不自動求值
- **關聯**：規格 §4.1、驗收 8

#### TC-X40　`+` `-` `@` 開頭
- **優先級**：P0
- **前置條件**：C 欄分別填 `+1+1`、`-1+1`、`@SUM(1,1)`
- **步驟**：同 X39
- **預期結果**：規格 §4.1 只寫了 `=`，但 CSV/Excel 公式注入的完整集合包含 `+ - @`（OWASP 建議還有 tab 與 CR）。**預期與 `=` 同樣當文字處理**；若 Rune 只處理 `=`，本用例記為缺陷並提給產品（缺口 W04）
- **關聯**：規格 §4.1

#### TC-X41　超長字串
- **優先級**：P1
- **前置條件**：`long.xlsx`（A2 十萬字、C2 十萬字）
- **步驟**：導入
- **預期結果**：拒絕並報長度超限；服務不崩、不 OOM、回應時間在數秒內。訊息裡不要回顯那十萬字
- **關聯**：規格 §3 欄 A/C、§4.2

#### TC-X42　合併儲存格
- **優先級**：P0
- **前置條件**：`merged.xlsx`：A1:L1 合併填「範例」；另備一份把 A2:A3 合併
- **步驟**：導入
- **預期結果**：規格未定義（缺口 W07）。合理期望是**明確拒絕並提示「請取消合併儲存格」**，而不是把合併區的非左上角單元格讀成空、進而報一堆「必填缺失」讓使用者一頭霧水
- **關聯**：規格 §4.2（未覆蓋）

#### TC-X43　空 sheet（只有表頭）
- **優先級**：P0
- **前置條件**：`empty.xlsx`
- **步驟**：導入

#### TC-X44　表頭正確但只交換兩欄
- **優先級**：P0
- **前置條件**：把 B、C 兩欄整列資料互換，表頭隨之互換
- **步驟**：導入
- **預期結果**：按規格 §4.1「表頭順序」要求 → 拒絕。這條與 X10 是一組，X10 驗「打亂」，本條驗「僅兩欄」的最小破壞，避免實作只比對「表頭集合相等」
- **關聯**：規格 §4.1

#### TC-X45　多餘的 M 欄有內容
- **優先級**：P1

- **預期結果**：規格未定義（缺口 W13）。合理期望是**忽略 M 欄並照常導入**（使用者常會加自己的欄位），或明確拒絕；兩個都可以，但要一致，且不能把 M 欄內容串進 L 欄

#### TC-X47　單元格型別錯位
- **優先級**：P1

### I 導入後一鍵執行

#### TC-X54　發佈並執行全流程
- **優先級**：P0

#### TC-X55　沒有可用 Agent 版本
- **優先級**：P1

#### TC-X56　一鍵執行時評分規則集版本從哪來
- **優先級**：P0
- **前置條件**：同 X54
- **步驟**：觀察發佈時用的 `scoringProfileVersionId` 是哪一個（預設規則集？最後一個？讓使用者選？）
- **預期結果**：必須有明確來源並在界面上可見。**這是規格缺口**：§5 第 1 步只說「發佈測試集新版本」，但四元組需要評分規則集版本，規格從頭到尾沒說它從哪來（缺口 W11）。若無 active 的評分規則集版本，一鍵執行應停下來說明而不是用空規則集硬跑
- **關聯**：規格 §5、`src/server/store.ts:688-701`

#### TC-X57　任一步失敗停在該步
- **優先級**：P1
- **前置條件**：準備一個已停用的 Agent 版本參與選擇
- **步驟**：一鍵執行時選到停用版本
- **預期結果**：停在該步並說明「Agent 版本已停用」，不自動略過、不建出會被閘門拒絕的實驗
- **關聯**：規格 §5「任一步失敗就停在該步」

#### TC-X58　導入的寫入類案例在只讀 Agent 上被攔截

- **前置條件**：導入一份含 J=寫入 案例的檔；選一個 `allowWrite=false` 的 Agent
- **步驟**：一鍵執行跑完
- **預期結果**：該案例被記為 `blocked`、不發請求、評分為 null；報告按既有 N/A 口徑處理（`blocked_readonly`），不能因此讓整批失敗
- **關聯**：規格 §5、`src/server/store.ts:985-1014`

## 四、規格缺口與待確認（建議在 Rune 動工前先拍板）

按影響排序，前四條會直接改變用例判定，不定清楚寫出來的測試也不算數。

| 編號 | 缺口 | 影響 | 建議 |
| --- | --- | --- | --- |
| W01 | `template_version` **存在哪個單元格**沒定義（「單獨一格」但沒說哪一格） | 造數無法對齊；校驗實作可任意選位置，日後改版難遷移 | 定成「填寫說明」sheet 的具名區域或固定座標（如 `B2`），寫進規格 |
| W02 | §4.3 的「僅導入通過的行」開關與 all-or-nothing **直接矛盾**，§8 又說「傾向先不做」 | Rune 可能兩種都做一半，導致預設路徑不再是整批 | V1.0 明確不做，從規格移除這段；要做就另開一版 |
| W03 | **重複導入**行為完全未定義（§4.4 只說「只做新建」） | 同一檔導兩次會產生兩個同名測試集，界面若不說清就是事故 | 規格補一段：同名時新建並在結果頁明示 |
| W04 | 公式注入只寫 `=`，沒寫 `+ - @` 與 tab/CR | 安全用例無法判定；只擋 `=` 等於沒擋 | 改成「以 `= + - @` 或 Tab/CR 開頭的單元格一律按文字存」 |
| W05 | 「表頭順序」與「表頭正確」的關係沒說死 | Rune 若按名稱匹配、用例按規格判拒絕，會吵一輪 | 二選一寫進規格，我這份用例已按「順序必須一致」寫，改就同步改 |
| W06 | 空 sheet / 零資料行未定義 | 可能生成 0 條草稿，直到發佈才報錯 | 前置校驗階段就拒 |
| W07 | 合併儲存格未定義 | 非左上角讀成空 → 使用者看到一堆莫名「必填缺失」 | 明確拒絕並提示取消合併 |
| W08 | 「C 必填」與「K 有值則忽略 C」衝突 | 多輪案例會被誤報必填缺失 | 改成「K 有值時 C 非必填」 |
| W09 | 「500 行」是否含表頭未定義 | 邊界用例的期望值差一行 | 寫成「資料行 ≤500（不含表頭）」 |
| W10 | E=規則時 G 有值、E=Rubric 時 F 有值，是忽略還是報錯 | 影響校驗嚴格度 | 建議忽略並在結果頁提示 |
| W11 | 一鍵執行用的**評分規則集版本來源**未定義 | 四元組第 3 項憑空出現，可重現性無從保證 | 規格補：預設用「預設評分規則集」，並在界面顯示 |
| W12 | 導入中斷（斷網／殺進程）的語義未定義 | 原子性只能靠實作自覺 | 明確寫「解析與寫入全程在一個交易內，中斷即回滾」 |
| W13 | 多餘欄（M 之後）、多餘 sheet、隱藏行列未定義 | 實作可能靜默丟資料或把鄰欄串進來 | 明確：多餘欄與多餘 sheet 忽略，隱藏行列照常讀取 |
| W14 | **壓縮炸彈**風險未提：xlsx 是 zip，5MB 可解壓出 GB 級 | 上傳限制形同虛設，可打爆內存 | 增加解壓後總大小與單元格總數上限（如解壓後 ≤100MB、單元格 ≤100 萬） |
| W15 | 測試集名稱取檔名，但檔案名長度與非法字元未定 | 超長檔名可能撞庫欄位限制或造成 UI 換行 | 截斷到 100 字並清掉路徑非法字元 |

## 五、執行順序建議

1. **先跑「模板 ↔ 校驗」是否自洽**：X01 → X02 → X51 → X52（round-trip 打不通，後面全是空談）
2. **再跑原子性四連**：X25 → X26 → X27 → X28（一條流程覆蓋四條，約 20 分鐘）
3. **然後安全與畸形**：X39 → X40 → X42 → X43 → X44（這批最容易出真缺陷）
4. **中斷類單獨安排**：X30 → X31 → X32 → X33，要殺進程，別和别人共用端口
5. **重複導入最後跑**：X34 → X35 → X36 → X38，等 W03 拍板後再定判定
6. 一鍵執行（X54–X58）放在 Agent 接入環境上跑，不要用 mock 冒充

工時估計：P0 約 2 小時，P1 約 1.5 小時，P2 約 30 分鐘；造 fixture 約 40 分鐘（可以腳本化，建議直接提交 `scripts/fixtures-excel.ts`）。
