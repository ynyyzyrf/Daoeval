## 1. 這是什麼

通用 AI Agent 評測與優化平台 V1.0。給需要對比多個 Agent（或同一 Agent 的多個版本）的人用：接入 Agent → 建測試集與案例 → 建實驗（凍結可重現四元組）→ 批量跑 → 規則評分 → A/B 報告 → 導出。

需求文檔（產品方 Vera 維護，改需求先看它）：
`D:\work\AgentStudyLLM\outputs\agent-eval-platform-v1-20261030\通用Agent評測平台V1.0-需求文檔.md`

現在能做的事：

- 接入 Agent：三步（連線 → 欄位映射 → 驗證預覽），驗證不過不能儲存；憑證只寫不讀。
- 測試集：建集、案例整批覆蓋（`PUT /api/test-sets/:id/cases`），沒有單條增刪改端點；批量選取（改類型／刪除，刪除有二次確認）、發佈不可變版本、停用版本。
- 實驗：可重現四元組閘門（測試集版本 + 評分規則集版本 + N + 各分支 Agent 版本），啟動時凍結快照；批量執行支援並發、暫停、繼續、取消、失敗分類。
- 評分：規則評分、七維度聚合、N/A 六類原因碼（不進分母、不當 0 分）。
- 報告：A/B 對比、改善／退步、樣本量與 95% 信賴區間、樣本不足提示、Token 資源消耗、案例下鑽到單條試驗（列表＋右側明細，不跳頁）。
- 導出：JSON／HTML／PDF，與頁面共用同一份皮膚 token。
- UI：Linear 淺色皮膚 v1.3、七項全局導航（概覽／搜尋／Agent／測試集／實驗／報告／設定）＋最近實驗、⌘K／⌘N／⌘↵／ESC、深連結直開（SPA fallback）。

## 2. 技術棧與目錄

- Node.js 22（pnpm），TypeScript ESM（`.ts` 直接跑，tsx 執行）。
- 後端：Fastify 5；前端：React 19 + Vite（無 UI 框架）。
- 資料庫：**SQLite（better-sqlite3）**，不是 Postgres、沒有 JSONB 模式。WAL 模式，單進程寫入。
- 隊列：任務與 run 已落 SQLite；worker 為單進程記憶體內註冊，沒有 Redis／BullMQ、沒有獨立 worker 進程。重啟後標記中斷，需使用者手動續跑。
- 憑證：AES-256-GCM 加密落庫（`src/server/crypto.ts`）。

## 3. 本地怎麼起

前置：Node 22、pnpm、本機有 Edge（僅 PDF 導出需要）。

```bash
pnpm install
pnpm run build:web     # 產生 web/dist（前端改動必跑）
pnpm start             # http://127.0.0.1:5280
```

服務同時在 `127.0.0.1:5199` 啟動模擬 Agent。首次啟動會自動建庫（`migrate()`），不需要建庫腳本、不需要 Postgres。

查驗：

```bash
curl http://127.0.0.1:5280/api/overview     # 200 JSON
curl -I http://127.0.0.1:5280/agents        # 200 text/html（SPA fallback）
pnpm run smoke                              # 55 條；只依賴 5199 的模擬 Agent，不需要 5280 主服務在跑
pnpm exec tsc -p tsconfig.json --noEmit     # 型別檢查
```

smoke 不覆蓋 HTTP 層：它直接 import store／adapter；HTTP 與前端測試仍缺。

環境變數（都有預設）：

| 變數 | 預設 | 說明 |
| --- | --- | --- |
| `AEVAL_PORT` | 5280 | 平台端口 |
| `AEVAL_MOCK_PORT` | 5199 | 模擬 Agent 端口 |
| `AEVAL_DATA_DIR` | `.data` | SQLite 與開發金鑰目錄 |
| `AEVAL_ENC_KEY` | 無（本地自動生成 `.data/dev-enc.key`） | base64 編碼的 32 bytes 憑證金鑰；生產必須注入 |

演示資料：設定頁「開發者工具 → 灌入示範資料」，或 `curl -X POST http://127.0.0.1:5280/api/demo/seed`。會建立 4 個模擬 Agent、測試集「基礎能力冒煙集」與三分支實驗。

API 端點（全部在 `src/server/routes.ts`）：meta／overview；agents（列表、詳情、preview、validate、建立、更新、版本、停用）；test-sets（列表、詳情、建立、案例、發佈）；scoring-profile-versions、dataset-versions；experiments（列表、建立、詳情、單條 trial、run、runs、metrics、export.json/html/pdf）；runs 的 pause／resume／cancel；demo/seed。

## 5. 關鍵約定（改動前必讀）

1. **三態證據**：`present`（有值）／`none`（明確空 `[]`）／`unavailable`（取不到，`null`）。取不到不能當「沒有工具調用」，該維度記 N/A，不進分母、不當 0 分。
2. **版本 append-only**：Agent 版本與測試集版本不可改、不可刪，只能停用；DB trigger 強制。改配置＝產生新版本＋diff。
3. **可重現四元組**：實驗級凍結「測試集版本 + 評分規則集版本 + N」；分支級各綁 Agent 版本；啟動時連案例內容、閾值、評分規則一起快照。缺一不得啟動。
4. **N/A 原因碼固定六類**：`no_cases`／`tool_evidence_missing`／`blocked_readonly`／`insufficient_samples`／`not_run`／`no_scoring_basis`，報告頂部按原因彙總。
5. **錯誤分類中文化**：顯示一律走 `ERROR_CLASS_LABELS`／`errorClassLabel()`，原始枚舉碼只放 `title` 或詳情；頁面、HTML、PDF 共用同一份表。10 類為：只讀攔截／逾時／認證失敗／端點不存在／限流／服務端錯誤／請求被拒／回應解析失敗／映射失敗／連線失敗，以 `ERROR_CLASS_LABELS` 為準。
6. **tokens.css 不准手改、組件不准硬寫色值**：token 唯一來源 `src/shared/skin.ts`，改完跑 `node scripts/gen-tokens.mjs`；驗收看 `grep -E "#[0-9a-fA-F]{3,8}" web/src/components/*.tsx` 必須 0 命中。導出件用 `renderTokensCss()`。
7. **皮膚以 v1.3 Linear 淺色為準**（`docs/皮肤规范-v1.3-Linear-淺色.md`），v1.0／v1.1／v1.2 作廢。卡片環形陰影、主按鈕近黑、靛藍只在選中列左線／focus／連結、資料等寬、行高 38；狀態一律「圓點＋單詞」，不用 pill；pill 只保留給類型、分類這類非狀態標識。
8. **側欄**：只許七項導航＋有資料才顯示的「最近實驗」；不得硬編項目、分組、人名，空資料整塊消失。
9. **憑證只寫不讀**：日誌、錯誤、請求摘要、導出件不得出現明文；請求摘要的敏感 header 已遮罩。
10. **適配器不硬編回應路徑**：Oumi／Dify 全走 `responseMap` 配置；新增平台＝加模板與 meta，不改 adapter。

## 6. 已知問題與技術債

- SQLite 單進程；換 Postgres 只動 `db.ts`＋`store.ts`，但 trigger 與外鍵 restrict 要原樣重建。
- 極端崩潰窗口：trial 已落庫但 run_task 未回寫時重啟，該條會按已完成計，可能缺評分。
- 「暫停中殺進程」路徑未實測（代碼上 paused 會被標 interrupted，但沒有自動化案例）。
- worker 為單進程記憶體內註冊，不支援多進程／多機部署。
- legacy 批次依 `created_at` 貪心分批推導，無法還原真實執行邊界，只作歷史參考。
- 導出 HTML／PDF 未顯示 run id，批次只能從 JSON 導出件辨識。
- PDF 導出依賴本機 Edge headless（`src/server/report.ts` 找 `msedge.exe`）；CI／Linux 會失敗，需換 puppeteer 或 headless chromium。
- 模擬 Agent 自 `/mock/*`，**不代表真實 Oumi／Dify 格式**；Oumi swagger 無 request/response schema（`docs/oumi/swagger.json`），實測前不要猜路徑。
- `scripts/` 裡的一次性 patch 腳本仍在版本庫，屬噪音。
- 導出 HTML 自包含但未做分頁優化；PDF 版面以 A4 直式列印。
- 多處文案是繁體中文硬寫，未做 i18n。
- 前端沒有單元測試，改 UI 要自己截圖核對（`scripts/shot.mjs`）。

## 8. 給 Codex 的操作建議

- git 提交只 `git add` 自己改的具體路徑，不要用 `git add -A`／`git add .`／`commit -a`；同一目錄可能有多個 Bot 並行改動，整包暫存會把別人的半成品帶進提交。

- **硬規則：所有驗證、探測、批量測試一律用臨時資料目錄**——`AEVAL_DATA_DIR=.tmp/verify-<時間戳>`（必要時連 `AEVAL_PORT`／`AEVAL_MOCK_PORT` 一起換），**永遠不在 `.data/` 上跑批量**。`.data/` 是使用者本機資料：mock 批量會頂掉使用者預設視角，接了真實 Agent 後更會直接燒掉真實調用與費用。本專案接手時就發生過一次（Codex 在主庫跑 mock 批量，事後備份後才清掉），這條不是建議。
- 動工前：`git status` 應乾淨；跑一次 `pnpm run smoke` 與 `pnpm exec tsc -p tsconfig.json --noEmit` 建立基線。
- 每輪改動後：`pnpm run build:web`（前端）＋ smoke；UI 改動用 `node scripts/shot.mjs <url> <out.png>` 直接截圖核對。
- 不要手改 `web/src/tokens.css`；不要往 `web/src/components/*.tsx` 寫色值。
- 不要改 `.data/`（本機資料）；不要把憑證寫進代碼或文檔。
- 需求有疑問先問產品（Vera），不要自行擴大範圍。
