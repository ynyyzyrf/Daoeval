## 主题一　可重现四元组冻结

不变量：一个实验的结论，必须能由「测试集版本 + 评分规则集版本 + N + 各分支 Agent 版本」唯一重建；四者缺一不得启动；启动后外部改动不得污染已有数据。

### TC-101　四元组齐备时可建立实验并冻结快照　⚑ 实测
- **优先级**：P0
- **前置条件**：已有已发布的测试集版本、active 的评分规则集版本、至少一个 active 的 Agent 版本
- **步骤**：
  1. `POST /api/experiments`，body 为 `{name, kind:"A", datasetVersionId, scoringProfileVersionId, repeats:1, branches:[{role:"baseline", agentVersionId}]}`
  2. `GET /api/experiments/{id}`，读 `frozen`
- **预期结果**：HTTP 201，返回 `{ok:true, experimentId}`；`frozen` 中同时存在 `dataset.versionId`、`scoring.versionId`、`repeats≥1`、`branches[].agentVersionId` 与 `branches[].agentVersionNo`
- **关联代码**：`src/server/store.ts:801-864`、`src/server/routes.ts:384-415`

### TC-102　冻结快照必须包含案例内容、规则与阈值　⚑ 实测
- **优先级**：P0
- **前置条件**：测试集里至少一条案例配了 `rule`（例如 `max_length`），评分规则集版本配了 `thresholds`
- **步骤**：`GET /api/experiments/{id}`，检查 `frozen.dataset.cases[*].rule`、`frozen.scoring.thresholds`、`frozen.branches[*].config`
- **预期结果**：案例级 `rule` 是完整 JSON 数组；`thresholds.minSamples` 是数字；`branches[].config` 含 endpoint、requestTemplate、responseMap、versionInfo。少任一项即 FAIL——快照缺内容等于四元组只冻了一半
- **关联代码**：`src/server/store.ts:816-834`

## 主题三　三态证据与 N/A

不变量：`present`（有值）/ `none`（明确空 `[]`）/ `unavailable`（取不到，`null`）三者语义不能混；取不到记为 N/A，**不进分母、不当 0 分**；六类原因码各自可区分。

### TC-301　present：有工具记录时正常判分
- **优先级**：P0
- **前置条件**：被测端点返回 `tool_calls: [{name:"web_search"}]`；案例规则 `[{kind:"tool_called", name:"web_search"}]`
- **步骤**：`POST /api/demo/seed` 后用 Oumi 分支跑一轮，读 `metrics.branches[baseline].dimensionResults[tool_capability]`
- **预期结果**：`na=false`，`value` 有值，`totalCases` 把该案例计入分母　⚑ 实测：`na=false value=1 分母=1`
- **关联代码**：`src/server/scoring.ts:102-112`、`261-281`

### TC-302　none：明确空数组判未通过，不是 N/A
- **优先级**：P0
- **前置条件**：被测端点返回 `tool_calls: []`（mock `/mock/empty-tools`）
- **步骤**：用该 Agent 跑一轮，读 tool_capability
- **预期结果**：`na=false`、`value=0`、该案例计入分母。语义是"这个 Agent 确实没调工具"，属于能力不足，不是测不了
- **关联代码**：`src/server/scoring.ts:106-108`、`src/server/adapter.ts:49-59`

### TC-303　unavailable：取不到时整维度 N/A，不进分母

## 主题五　队列续跑

不变量：跑批中进程被杀，重启后状态是 `interrupted` 而不是"完成"；**不自动续跑**；手动续跑后同一 trial 不得重复执行；并发上限守住。

### TC-501　跑批中杀进程：重启后必须标为 interrupted　⚑ 实测
- **优先级**：P0
- **前置条件**：一个慢批次（mock `/mock/slow` 分支，N=4，concurrency=2，共 24 条）
- **步骤**：
  1. 起 run，等 `done` 到 6/24
  2. 直接 `Stop-Process -Id <5282 的 node pid> -Force`（或用任务管理器杀掉）
  3. 用同一数据目录、同端口重启
  4. 读启动日志与 `GET /api/runs/{id}`
- **预期结果**：启动日志出现「啟動恢復：1 個執行因重啟中斷，N 條試驗已退回待跑」；run 状态 `interrupted`；**已完成的 6 条 trial 仍在**；`interrupted_at` 有值；`finished_at` 为空
- **关联代码**：`src/server/store.ts:295-322`、`src/server/index.ts:13-18`

### TC-502　手动续跑不重复执行　⚑ 实测

  1. 记录续跑前的 trial 数（应为 6）

### D01　Agent 的 `targeting` 不落库、不参与 diff，改 targetId 会被判"配置未变更"
- **状态**：已修复（`216bf66`，2026-10-31 复验通过）——`agent` 表加 `targeting` 欄位、`configFromRow` 還原、`diffConfig` 納入比較；本条保留作回归
- **发现于用例编号**：TC-211（辅助：TC-202）
- **严重度**：S1
- **现象**：`createAgent` 只把 name/endpoint/auth/requestTemplate/responseMap/versionInfo/allowWrite 写进 `agent` 表，没有 `targeting` 字段；`configFromRow` 也不还原它。因此 `GET /api/agents/{id}` 返回的 config 里永远没有 targeting。
- **复现**：
  1. 用带 `targeting:{targetType:"Group", targetId:"group-1"}` 的 config 建 Agent
  2. `GET /api/agents/{id}` → config 里没有 targeting（`agent_version.snapshot` 里有）
  3. 只改 `targeting.targetId` 为 `agent-9`，`POST /api/agents/{id}`
- **预期**：产生新版本，diff 里出现 `targeting`
- **实际**：`400 {"error":"配置未變更，未產生新版本"}`
- **影响范围**：Oumi 接真实端点后，前端按 `GET` 回来的配置再保存一次，就会静默丢掉 targeting；`callAgent` 用 `config.targeting` 判断走会话模式还是单次 HTTP，丢了这个字段就会用错调用路径。在真实端点接入前属未爆雷，接入后直接阻断。
- **关联代码**：`src/server/store.ts:144-160`（configFromRow）、`383-403`（diffConfig）、`428-455`（createAgent）

### D02　资源消耗的"样本数"与"平均值"用的不是同一批试验
- **状态**：未修复（截至 `216bf66`，2026-10-31 复查）
- **发现于用例编号**：TC-412
- **严重度**：S2
- **现象**：`computeMetrics` 计算 token 平均时，只要存在一条 prompt/completion/total 三项齐全的试验，就只在这批"齐全"的试验上取平均；但 `samples` 计的是"任意一项有值"的试验数。
- **复现**：构造 3 条试验，prompt tokens 分别为 1000、1000、100（后一条三项齐全），N=1
- **预期**：`samples=3` 时平均值应为 700
- **实际**：`{"promptTokens":100,"completionTokens":20,"totalTokens":120,"samples":3}`——平均值只来自 1 条，却标着样本 3
- **影响范围**：报告"資源消耗"栏的平均 Token 会偏高或偏低，且看不出实际参与计算的样本量。使用者拿它做成本估算会错。
- **关联代码**：`src/server/scoring.ts:364-387`

### D03　`insufficient_samples` 这个 N/A 原因码永远出现不了
- **状态**：未修复（截至 `216bf66`，2026-10-31 复查）
- **发现于用例编号**：TC-305
- **严重度**：S2
- **现象**：`scoring.ts:314-320` 的 `else if (eligible === 0 && naCode === null)` 分支不可达——进入循环后每个案例要么把 `naCode` 设为 `blocked_readonly`/`no_scoring_basis`，要么让 `eligible` 自增，两者不可能同时不发生。因此 `naCode` 在 `eligible===0` 时必然非空。
- **复现**：按 TC-305 构造六个场景，只有五类原因码出现过；冻結 N=3 只跑 1 次时 `na=false`、`sampleShort=true`，没有任何 N/A
- **预期**：六类原因码都能区分"没测"与"测不了"
- **实际**：`insufficient_samples` 是死代码；"样本不足"退化为一个布尔提示，报告不会因此拒绝下结论
- **影响范围**：报告顶部的原因汇总少了最重要的一类——"数据量不够，结论不可信"。这一条直接影响产品声称的"样本不足提示"。
- **关联代码**：`src/server/scoring.ts:294-320`、`scoring.ts:337-348`（`stability` 部分用 `>= repeats` 另有判断）

### D04　runId 不存在或不属于该实验时，指标与导出的降级行为不一致
- **状态**：未修复（截至 `216bf66`，2026-10-31 复查）
- **发现于用例编号**：TC-405、TC-406
- **严重度**：S2
- **现象**：`getRunSummary(不存在的id)` 返回 null，`routes.ts:496` 的 404 判断被 `selected &&` 短路，于是返回 200 + 全维度 `not_run`；导出侧 `buildReport` 把 `run` 置 null 后照常出报告。
- **复现**：
  1. `GET /api/experiments/{id}/metrics?runId=run_nonexistent` → `200`，所有维度 `not_run`
  2. `GET /api/experiments/{id}/export.json?runId=run_nonexistent` → `200`，`run=null`、`trialCount=0`

- **实际**：metrics 把"不存在"显示成"尚未执行"；export 无论哪种情况都出 200 空报告
- **影响范围**：拼错 id、或前端拿着旧 runId 请求，会得到一份看起来正常、实际为空的报告并可能被当作交付物导出。
- **关联代码**：`src/server/routes.ts:489-497`、`531-566`、`src/server/report.ts:112-117`

### D05　run 可以用不同的 N 启动，但指标与报告永远按冻结的 N 聚合
- **状态**：未修复（截至 `216bf66`，2026-10-31 复查）
- **发现于用例编号**：TC-407
- **严重度**：S1
- **现象**：`POST /api/experiments/{id}/run` 接受 `body.repeats` 并写进 `run.repeats`；但 `/metrics` 返回的 `repeats`、`computeMetrics` 的 `repeats` 参数、报告里的 `experiment.repeats` 全部取 `frozen.repeats`。
- **复现**：冻結 N=1 的实验，用 `{repeats:3, branchIds:[两个分支]}` 启动
- **预期**：指标与报告的 N 应当是这次实际执行的 3（或明确拒绝非冻结 N 的启动）
- **实际**：`run.total=36`（说明确实跑了 3 次），但 `metrics.repeats=1`、导出件 `experiment.repeats=1`，报告"重複成功比例"判为「不適用（N=1）」，`stability.repeatAllSuccessRatio` 的分母也按 1 算
- **影响范围**：跑了 3 遍的结果被当成跑 1 遍来聚合，稳定性指标失效，"重複成功比例"这一项在 N>1 的实际执行里显示不出来。同样是 N=4 的续跑实测里复现（`repeats=1`）。
- **关联代码**：`src/server/runner.ts:80`、`src/server/routes.ts:502,515`、`src/server/report.ts:119,246-252`

### D12　实验状态由全部 trial 推导，与 run 状态脱钩
