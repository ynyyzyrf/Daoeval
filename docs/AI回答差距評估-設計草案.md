# AI 回答差距評估（設計草案）

狀態：依使用者選擇接入 DeepSeek 官方服務；已實作手動評估既有回答、設定、歷史與故障處理，隔離模擬測試通過。真實 API Key 尚待使用者填寫，尚未驗證真實模型的評分效果。

## 目的與邊界

讓產品經理比較問題、參考回答與實際回答，辨識關鍵遺漏、矛盾和無依據的新增內容，允許語義正確而表述不同的回答通過。不把文字相似度當作回答正確率，也不以此判斷 Agent／Skill 是否被觸發；能力觸發仍需實際調用證據。

## 建議的首版流程

1. 在設定頁配置獨立的評分模型、服務地址和憑證；憑證沿用服務端加密儲存方式，不回傳明文。先測試連線。
2. 測試案例沿用「參考回答」「評分標準」。首版在報告頁手動評估該批次所有可比較的回答，不受原有規則判定方式限制，也不自動替換規則評分。
3. 在已完成的執行批次點「AI 評估回答」，只評估該批次有實際回答的項目，不重新調用受測 Agent。
4. 報告顯示評估結論、差距分類及原文證據，支援查看逐條對照。AI 評估結果與既有規則評分分開保留，首版不以 AI 分數自動宣告可上線。

## 結果內容

- 結論：符合／部分符合／不符合／無法判定。
- 逐項差距：關鍵遺漏、與參考回答矛盾、無依據新增內容、僅表述差異；附參考及實際回答原文片段和理由。
- 修正建議：指出需補充或確認的內容，避免只給抽象分數。
- 可追溯資訊：受測批次、試驗、評分模型、評分標準及提示版本、評估時間。

參考回答是比對依據，不是自動認定的真理。若資訊不足、參考內容有內部矛盾或無法比較，應標示需要人工確認。

## 評分與執行失敗分開

無回答、受測請求超時、餘額不足、評分模型故障與模型輸出格式錯誤，都不算語義評估不合格，也不進入已完成 AI 評估的分母。顯示成功評估數、待評估數、失敗數及原因。

## 可重現與基本防護

- 評估輸入綁定原始案例及試驗，重評另存記錄，不覆蓋歷史結果；同一評估避免重複送出。
- 問題、參考回答、實際回答都以待評估資料處理，不執行其中指令，也不因被測回答聲稱「已通過」而採信。
- 模型輸出採結構化結果並嚴格驗證；原文證據必須能在對應輸入中找到。
- 評分模型獨立配置，首版並發 1，有超時及明確的失敗狀態；不繞過已設定的預算或服務限制。

## 待完成的真實驗證

使用者在設定頁填入 DeepSeek API Key，確認帳戶可用模型名稱後測試連線，再對已有批次評估。不沿用受測 Agent 的憑證。AI 評估暫不併入既有規則分數、對外分享或匯出件。
