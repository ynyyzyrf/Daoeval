# 评估模型管理改版

## 目标与依据

将原设置页中的常驻表单改为独立的模型管理流程，沿用 Daoeval 的导航、颜色、按钮和抽屉组件。

原页面的问题：列表藏在下拉框里；查看配置与编辑草稿混用同一空间；保存、测试、设为当前模型三个操作并列但前置条件不清；未配置时展示整张禁用表单。

参考 [Dify 模型供应商](https://docs.dify.ai/en/cloud/use-dify/workspace/model-providers) 的独立管理入口和按需配置，以及 [Langfuse LLM Connections](https://langfuse.com/docs/administration/llm-connection) 的连接列表与高级设置分层。保留现有兼容接口与数据模型，不扩展为供应商插件系统。

## 方案

用户选择侧栏新增“评估模型”，路径 `/models`，原设置页保留审计、术语与版本信息。相比设置子页，这个入口更容易从评估工作流找到。

- 页面首屏显示默认评估模型摘要和已保存模型列表，列表直接提供编辑、连接测试和设为默认。
- 尚未配置时展示一个明确的“添加模型”入口，不展示空编辑表单。
- 新增、编辑使用右侧抽屉，分为模型信息和连接设置。新增提供 DeepSeek、自定义服务两个模板，均使用现有 OpenAI 兼容协议。
- 保存只负责持久化配置；连接测试与默认模型切换放在列表中。已有默认模型时，添加配置不会自动替换。
- 说明文字靠近对应字段，兼容性细节折叠展示；Key 只在抽屉输入，列表不展示凭证。
- 放弃未保存修改需确认，保存期间避免重复提交。抽屉支持 Escape、焦点约束和关闭后焦点返回。
- 测试结果为本次页面会话状态，刷新后显示未测试，不宣称持久的可用性监控。
- 默认切换仍仅影响新批次；原模型配置及评估历史继续保留。

## 实施与验收

1. 添加前端路由、侧栏、面包屑、命令搜索和报告页跳转。
2. 复用现有 API 实现列表、空态和抽屉，新增局部样式，修复复用抽屉的焦点管理。
3. 验证直达路由、空态、新增/取消、模型列表、编辑、测试与默认切换；交互验证使用隔离数据，实际项目不灌入演示配置。
4. 类型检查、生产构建和现有模型专项检查通过后更新本地预览；在桌面及窄屏检查布局。
